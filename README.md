# Guru99 Banking Application – Manual Testing Project

## 📌 Project Overview

This repository contains the complete Manual Testing documentation and artifacts created for the **Guru99 Banking Application**.

The project was executed following the **Software Testing Life Cycle (STLC)** to validate the functionality, reliability, and usability of a banking web application.

The primary objective of this project was to gain hands-on experience in real-world software testing activities, including requirement analysis, test planning, test case design, test execution, defect reporting, retesting, regression testing, and test documentation.

---

## 🎯 Project Scope

The testing process covered multiple banking modules to ensure that the application functions according to business requirements and provides a seamless user experience.

### Modules Tested

* Login
* New Customer
* Edit Customer
* New Account
* Edit Account
* Deposit
* Withdrawal
* Fund Transfer
* Balance Enquiry
* Mini Statement
* Custom Statement
* Change Password
* Logout

---

## Testing Activities Performed

### 1. Requirement Analysis

* Reviewed and analyzed the Software Requirement Specification (SRS).
* Identified business requirements and testing scope.
* Derived test scenarios from functional requirements.

### 2. Test Scenario Creation

* Prepared comprehensive test scenarios for all application modules.
* Covered positive, negative, and boundary test cases.

### 3. Test Case Design

Created detailed test cases including:

* Test Case ID
* Test Scenario
* Preconditions
* Test Steps
* Test Data
* Expected Result
* Actual Result
* Status (Pass/Fail)

### 4. Test Execution

* Executed all designed test cases.
* Recorded execution results and observations.
* Validated application behavior against expected outcomes.

### 5. Defect Reporting

Identified and documented defects with:

* Bug ID
* Severity
* Priority
* Steps to Reproduce
* Expected Result
* Actual Result
* Status

### 6. Retesting

* Verified defects after fixes were implemented.
* Ensured that reported issues were resolved successfully.

### 7. Regression Testing

* Re-tested impacted modules after defect fixes.
* Confirmed that existing functionalities remained unaffected.
